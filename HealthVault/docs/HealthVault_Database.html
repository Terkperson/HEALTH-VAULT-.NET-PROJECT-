HealthVault relational database

Complete SQL Server catalog for the 2-week MVP. Identity, patients, staff, appointments and medical records — designed so role reassignment and record deletion can be added later without a schema rewrite.

EngineSQL Server 2019+
DatabaseHealthVaultDb
Tables18
ORMEF Core 8
AuthIdentity + JWT
Run the scripts in database/ in order, from SSMS, Azure Data Studio, or any SQL Server workbench: 01_CreateDatabase.sql → 02_CreateTables.sql → 03_SeedData.sql. Then start the API so Identity can hash the demo passwords. Role changes (SRS FR-20) use 04_AssignRole.sql.

1. How to run in a workbench

  1. Connect to your SQL Server instance (Windows auth or SQL login).
  2. Open database/01_CreateDatabase.sql and execute. This creates HealthVaultDb.
  3. Open 02_CreateTables.sql (it already issues USE HealthVaultDb) and execute.
  4. Open 03_SeedData.sql and execute lookups + roles.
  5. In src/HealthVault.Api/appsettings.json set ConnectionStrings:DefaultConnection to your server. Examples:
    Windows auth: Server=localhost;Database=HealthVaultDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=True
    SQL login: Server=localhost;Database=HealthVaultDb;User Id=sa;Password=YourPassword;TrustServerCertificate=True;MultipleActiveResultSets=True
  6. First API start runs EF migrations (if you use them) and seeds demo users with hashed passwords.
Do not insert demo users by hand. ASP.NET Identity stores a salted hash in AspNetUsers.PasswordHash. The seeder creates: admin@healthvault.com / Admin@12345, staff@healthvault.com / Staff@12345, nurse@healthvault.com / Staff@12345, patient@healthvault.com / Patient@12345.

5. Views shipped with the script

  • vw_PatientDirectory — searchable patient list with age, gender, blood group.
  • vw_AppointmentBoard — date board with patient, clinician, department, status.

6. What was deliberately not modelled

  • No delete flag on medical records (feature cut).
  • No notifications, SignalR, Blob URIs, Key Vault, FHIR, or audit-log table (out of scope §2.3).
  • Role-assignment UI tables are not needed — roles already live in Identity.
